# Bounder website

This repository contains the public website for [bounder.io](https://www.bounder.io/).

Bounder is an open reference architecture for trustworthy physical interlocks — the last check between a digital decision and a machine that moves. The website presents the current project, integration model, interactive simulator, development status, and roadmap towards hardware validation.

The public source here is the website and JavaScript browser laboratory. The canonical Go decision engine is maintained in the private producer repository `NellInc/Bounder-from-org`, which is not publicly readable. Public fixtures support local verification; independent producer regeneration requires access to that separate checkout. See the [developer contract guide](guides/INTEGRATION.md#developer-contract-walkthrough) for signed bytes, examples, and failure semantics.

Repository-only material is not published: `tests/` holds the unit, contract and
browser suites; `scripts/` holds the build, verification and release tooling;
`system/`, `_wiki/` and `_contprompts/` hold the system descriptor and agent
documentation.

The `docs/` directory is the preserved Squarespace-era clone. It is a legacy
snapshot, not the source for new content. GitHub Pages must be configured with
**GitHub Actions** as its source: `.github/workflows/deploy-pages.yml` runs
`npm run verify` and publishes only the allowlisted `_site` artifact described
under [Deployment](#deployment). Do not switch the Pages source to a branch and
folder — that bypasses the allowlist and would publish `docs/`, `tests/`, and
repository automation.

## Preview

```bash
node scripts/serve-site.mjs --root . --port 8000
```

Open `http://127.0.0.1:8000/`. `python3 -m http.server 8000` also works for a
quick look. Release claims use the built `_site` artifact, which
`npm run test:browser` serves the same way.

## Validation

```bash
# Inspect current repositories, provenance, release, and holds.
npm run inspect

# Derive the least expensive sufficient checks for the current change.
npm run check:changed

# Execute the selected checks and emit a machine receipt.
npm run verify:changed

# Fast unit suite, then the per-file coverage gate. Browser-only modules are
# reported separately and proved by the browser suite.
npm test
npm run test:coverage

# Browser-level responsive, accessibility, failure, and keyboard checks.
npm run test:browser

# Assemble and byte-check the exact allowlisted publication artifact.
npm run build

# Run the complete local candidate gate and emit a machine receipt.
npm run verify

# Deterministic design lint. Triage results rather than bulk-fixing.
node_modules/.bin/impeccable detect .
```

`npm run build` assembles the exact GitHub Pages payload in `_site/`. A release
deliberately uses two commits. First, finalise every pinned file, including
`CHANGELOG.md`, `README.md`, and `VERSION`, review the staged changes, and create
source commit A. Commit A cannot describe its own seal, so its CHANGELOG entry
stays `(source candidate, unsealed)`; the same commit relabels the previous
entry with the manifest that sealed it, or records that it was published without
one. Then generate the manifest with commit A as its provenance:

```bash
git commit -m "release: prepare Bounder vX.Y.Z sources"
SOURCE_COMMIT="$(git rev-parse HEAD)"
BOUNDER_PRODUCER_ROOT=<path to a clean NellInc/Bounder-from-org checkout> npm run verify:producer
npm run verify
npm run release:manifest:v2 -- \
  --publisher-commit "$SOURCE_COMMIT" \
  --producer-receipt artifacts/producer-derivation/latest.json \
  --verification-receipt artifacts/verification/latest.json
```

The generator requires commit A to exist locally as a Git commit. Every pinned
path in it must be an ordinary non-executable Git blob whose bytes equal the
working-tree source. After the complete validation gates pass, commit the new
manifest separately as manifest commit B. Never amend source commit A after
generating the manifest; any source change requires a new source commit and a
newly generated manifest.

Before publishing, verify desktop and mobile layouts, keyboard focus, one `<h1>` per page, local links and fragments, images, console errors, and the contact success state without submitting the form. The browser suite automates the deterministic parts of this release gate.

The simulator never decides whether a scenario is allowed. It loads same-origin
`bounder-receipt/v1` fixtures generated by the Go interlock in the private
`NellInc/Bounder-from-org` producer repository. This public repository owns
presentation, verification, publication, and release sealing. The producer owns the decision, policy,
checkpoint, resilience, and private observability contract semantics; this site publishes byte-identical
copies of its thirteen shared schemas (the manipulator preview is not yet one of them).

The browser can verify a Fleet envelope locally, but it does not mint authority
or substitute for the Go interlock. Verify clean regeneration from a current
producer checkout:

```bash
BOUNDER_PRODUCER_ROOT=<path to a clean NellInc/Bounder-from-org checkout> npm run verify:producer
```

The path is not discovered: `scripts/verify-producer-derivation.mjs` fails fast
unless `BOUNDER_PRODUCER_ROOT` is set or `--producer-root` is passed, as
`.github/workflows/receipt-drift.yml` does with `../producer`.

See [`guides/INTEGRATION.md`](guides/INTEGRATION.md) for the complete Creed Space Fleet to Bounder contract and platform-adapter model.

## Project code

The canonical Go decision producer lives in the private
`NellInc/Bounder-from-org` repository. This public reference site lives in
[`NellInc/Bounder`](https://github.com/NellInc/Bounder). Release manifest v2
records their full commit identities separately, embeds exact generator input,
contract, and output hashes, and labels deployment and live observation as
separate proof classes.

Public users without producer-repository access can verify website source,
contracts, browser behaviour, release bytes, and published hashes. Independent
producer regeneration additionally requires access to the private immutable
producer revision. A future public mirror or reviewable source bundle would
close that public reproducibility gap.

## Deployment

GitHub Pages serves a deliberately allowlisted artifact assembled by
`npm run build`; historical snapshots, tests, working files, and repository
automation are excluded. After a deployment, verify both
`https://www.bounder.io/` and `https://bounder.io/`, the custom 404 page, the
canonical metadata, and `/.well-known/security.txt`.

### Design-lint status

Static and live-page Impeccable checks currently report zero findings. Any future
layout, contrast, broken-image, or interactive-target finding is a release
blocker until it is fixed or narrowly documented with rendered evidence.
