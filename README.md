# Bounder website

This repository contains the public website for [bounder.io](https://www.bounder.io/).

Bounder is an open reference architecture for trustworthy physical interlocks. The website presents the current project, integration model, interactive simulator, verified software status, and explicit hardware limitations.

## Canonical site

The root directory is the canonical website:

| File | Purpose |
|---|---|
| `index.html` | Project positioning, architecture, applications, maturity, and contribution path |
| `simulator.html` | Interactive 3D demonstration of local interlock decisions and protection rules |
| `simulator.js` and `simulator.css` | Three.js scene, scenario logic, accessibility, and responsive simulator presentation |
| `staging-feed.js` | Optional read-only Creed Space staging evidence loader with strict validation and deterministic fallback |
| `data/bounder-staging-pilot.v1.json` | Recorded 100-Guardian pilot across six physical platform classes |
| `simulator-world.js` | Town geometry, named building footprints, and collision-checkable route waypoints |
| `data/bounder-receipts.v1.json` | Deterministic decisions generated by the canonical Go interlock |
| `data/creedspace-bounder-golden-v1.json` | Cross-language Ed25519 Fleet policy vector used by the browser verifier |
| `data/creedspace-bounder-roundtrip-v1.json` | Signed receipt exported by the real Go guardian from that exact Fleet vector |
| `schemas/` | Published receipt and receipt-bundle JSON schemas |
| `release/` | Immutable SHA-256 integrity manifests for each reference release |
| `vendor/three/` | Pinned, self-hosted Three.js 0.180.0 runtime and licence |
| `tests/` | Route-clearance, receipt-contract, and runtime-dependency invariants |
| `contact.html` | Formspree-backed contact route |
| `privacy.html` | Current website privacy notice |
| `terms.html` | Website and research-software terms |
| `404.html` | GitHub Pages error page |
| `styles.css` | Shared responsive design system |
| `sitemap.xml` and `robots.txt` | Search discovery |
| `CNAME` | `www.bounder.io` custom domain |
| `LICENSE` and `NOTICE` | Apache-2.0 project licence and attribution notice |

The `docs/` directory is the preserved Squarespace-era clone. It is a legacy snapshot, not the source for new content. GitHub Pages should deploy `main` from `/`.

## Validation

```bash
# Route, receipt, archive, policy-verification, and dependency invariants.
npm test

# Browser-level responsive, accessibility, failure, and keyboard checks.
npm run test:browser

# Deterministic design lint. Triage results rather than bulk-fixing.
npx --yes impeccable@3.2.1 detect .
```

`npm run build` assembles the exact GitHub Pages payload in `_site/`. For a
release, update all pinned files first, bump `VERSION`, then run
`npm run release:manifest` as the final content step before validation.

Before publishing, verify desktop and mobile layouts, keyboard focus, one `<h1>` per page, local links and fragments, images, console errors, and the contact success state without submitting the form. The browser suite automates the deterministic parts of this release gate.

The simulator never decides whether a scenario is allowed. It loads same-origin
`bounder-receipt/v1` fixtures generated by the Go interlock in
[`NellInc/Bounder`](https://github.com/NellInc/Bounder). The receipt drift
workflow compares the published fixtures, schemas, and signed Fleet vector with
that canonical repository. The browser can verify a Fleet envelope locally, but
it does not mint authority or substitute for the Go interlock. Regenerate the
website fixtures from a sibling checkout:

```bash
CANONICAL=../Bounder-Drone
"$CANONICAL/scripts/generate-web-receipts.sh" "$(pwd)/data/bounder-receipts.v1.json"
"$CANONICAL/scripts/run-evidence-suite.sh" "$(pwd)/data/bounder-fleet-evidence.v1.json"
cp "$CANONICAL/contracts/creedspace-bounder-golden-v1.json" ./data/
cp "$CANONICAL/contracts/creedspace-bounder-roundtrip-v1.json" ./data/
cp "$CANONICAL/contracts/"*.schema.json ./schemas/
```

See [`guides/INTEGRATION.md`](guides/INTEGRATION.md) for the complete Creed Space Fleet to Bounder contract and platform-adapter model.

## Project code

The canonical interlock implementation and this public reference site live in
[NellInc/Bounder](https://github.com/NellInc/Bounder). The release manifest pins
the exact canonical interlock revision used to generate the published evidence.

## Deployment

GitHub Pages serves a deliberately allowlisted artifact assembled by
`npm run build`; historical snapshots, tests, working files, and repository
automation are excluded. After a deployment, verify both
`https://www.bounder.io/` and `https://bounder.io/`, the custom 404 page, and the
canonical metadata.

### Design-lint status

Static and live-page Impeccable checks currently report zero findings. Any future
layout, contrast, broken-image, or interactive-target finding is a release
blocker until it is fixed or narrowly documented with rendered evidence.
